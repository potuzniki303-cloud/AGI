# Миры

Среда для экспериментов с обучением без backprop. Чистый numpy, torch не нужен:
мир не должен зависеть от того, на чём написан агент.

## Что здесь есть и чего нет

Мир умеет: кормить, брать плату за существование, убивать и позволять делиться.

Мир **не** умеет и не должен уметь:

1. читать или писать веса агента;
2. вычислять для агента скаляр «хорошо/плохо» — награду, фитнес, счёт;
3. сортировать или ранжировать агентов;
4. решать, кто размножится: деление — событие физики, а не операция отбора;
5. заглядывать в геном — он вызывает `spawn()` и не знает, что внутри.

Статистика в `runner.py` считается **для человека**. Она никуда не возвращается.
Как только средняя продолжительность жизни начнёт на что-то влиять, она станет
функцией приспособленности, и конструкция схлопнется в обычный генетический
алгоритм. Тест `test_world_only_calls_act_and_spawn` сторожит границу.

## Подключить агента

Два метода, больше ничего:

```python
class MyAgent:
    def act(self, observation) -> int:
        """observation — float32 длины world.observation_size.
        Возврат — индекс действия в [0, world.action_size)."""

    def spawn(self, rng) -> "MyAgent":
        """Потомок: мутированный геном + СЛУЧАЙНЫЕ веса."""
```

Про случайные веса — это не придирка. Если веса наследуются, схема вырождается
в обычную нейроэволюцию, ту самую, которую мы отвергли. Ре-рандомизация при
каждом рождении механически запрещает геному протащить готовый ответ: агент,
который работает после случайной инициализации, действительно научился при
жизни, иначе он бы не работал вообще.

Стохастичность выбора действия — на твоей стороне. Мир не сэмплирует за агента,
иначе часть политики окажется в руках дизайнера. Детерминированный `argmax` в
рекуррентной сети залипает в неподвижную точку, так что шум нужен.

```python
from world import make, simulate

w = make("forage", seed=1)
print(w.describe())          # размер входа, число действий, вся физика

h = simulate(w, lambda rng: MyAgent(w.observation_size, w.action_size, rng),
             steps=5000)
print(h.summary())
```

`mind_factory` вызывается только для начальной популяции и должен возвращать
независимые случайные геномы. Все последующие тела появляются исключительно
через `spawn()` своих родителей.

## Миры

| имя | что проверяет |
|---|---|
| `forage` | базовый. Выживает ли вообще хоть кто-то |
| `seasons` | ресурс нестационарен во времени |
| `patches` | ресурс структурирован в пространстве |
| `shift` | сенсомоторика ломается посреди жизни |
| `two_foods` | что съедобно — геном знать не может в принципе |

Последние два главные. Они устроены так, что замороженные веса их физически не
решают: ответ либо меняется внутри жизни (`shift`), либо разыгрывается заново
при каждом рождении (`two_foods`). Если агент их проходит, значит он несёт
способ найти решение, а не само решение. Это ровно эксперимент
Najarro & Risi (NeurIPS 2020).

## Как читать числа

`python3 experiments/demo_worlds.py` гоняет заглушки. Две отметки на линейке:
`RandomMind` — снизу, `GreedyMind` (зашитый таксис) — сверху. Разрыв между ними
и есть место, в котором живёт эволюция.

```
forage      random: вымерли на 165     greedy: популяция 29, 19 поколений
patches     random: вымерли на 191     greedy: популяция 29, 40 поколений
seasons     random: вымерли на 165     greedy: популяция 17 (колеблется)
shift       random: вымерли на 115     greedy: популяция 30
two_foods   random: вымерли на 160     greedy: популяция 14
```

Что тут важно:

- **Популяция — плохая мера компетентности.** Её потолок задаёт скорость
  отрастания еды, а не качество агентов. В `shift` greedy держит те же 30, хотя
  каждое тело ломается на 60-м такте. Читать надо продолжительность жизни, а в
  `shift` конкретно её хвост (p90), а не медиану.
- **`greedy` в `two_foods` даёт половину** от `forage` (14 против 29). Это цена
  зашитого ответа: полярность бросается монеткой при каждом рождении, и «иди к
  типу 1» верно ровно у половины тел. Агент, выясняющий полярность внутри жизни,
  должен выходить на уровень `forage`, а не на половину.

## Ручки

Главная — `max_food`, потолок стоячего запаса **на каждый тип еды**. Через него
задаётся давление отбора, и считается оно так:

```
доход случайного ходока за шаг = плотность_еды * food_energy
расход за шаг                  = cost_per_step
```

При дефолтных 25 и 1.0 безубыточность — плотность 0.04, то есть 23 клетки из
576. Потолок стоит 16, поэтому блуждание убыточно. Поднимешь потолок выше 23 —
давление исчезнет, и случайные ходоки будут процветать наравне с компетентными.

Потолок именно по типу, а не общий. С общим мир с несколькими типами еды
заклинивает: несъедобный тип копится, занимает всю квоту, съедобный перестаёт
отрастать, и чем лучше агент различает типы, тем вернее он себя уморит. Этот
баг здесь уже был, на него есть тест.

Остальное:

- `regrow_per_step` — ёмкость среды. Устойчивая популяция ≈
  `regrow_per_step / (cost_per_step / food_energy)`. При дефолтах — около 30.
- `energy_at_birth` — запас хода на поиск первой еды. **Если холодный старт
  слишком суров** (вся начальная популяция вымирает раньше, чем эволюция
  что-то найдёт) — крутить надо это, вместе с `initial_population`.
- `food_decay` — гниение, по умолчанию выключено. Включи, если агенты
  выродятся в стратегию «стоять и ждать, пока еда отрастёт под ногами».
- `boundary` — `"wrap"` (тор, по умолчанию) или `"clamp"` (стены). На торе нет
  углов, в которых можно залипнуть, и статистика однороднее.
- `allow_stay` — пятое действие «стоять». По умолчанию выключено, чтобы не
  плодить вырожденный аттрактор.

## Сенсоры

Форма наблюдения влияет на обучаемость сильнее, чем правило пластичности.

`AntennaSensor` — основной. Направленная близость до ближайшей еды. Его выходы
стоят **в том же порядке, что действия**: сенсор 0 отвечает за то же
направление, что действие 0. Это не косметика. Приближение к еде усиливает
сенсор того направления, в котором ты идёшь, поэтому правильная пара
сенсор/действие коррелирована сильнее неправильной — и разницу создаёт
геометрия мира, а не оценка снаружи. На аллоцентрической сетке таких
ассоциаций 25x25 разных, и ни одна не обобщается.

Дальность по умолчанию не ограничена: тело всегда видит ближайшую еду, где бы
она ни была, поэтому мир заведомо проходим и первый эксперимент проверяет
правило обучения, а не разведку. `max_range` превращает задачу в поиск вслепую —
она намного тяжелее, браться стоит уже с работающим таксисом.

Собрать свой:

```python
from world.sensors import AntennaSensor, Interoception, PatchSensor

w = make("forage")
w.sensor = AntennaSensor("food", n_dirs=8) + AntennaSensor("agents", 4) \
         + Interoception(("energy", "age"))
# присваивать до reset(); observation_size обновится сам
```

## Свой мир

Наследуйся от `World` и переопределяй хуки, а не `step()`:

```python
from world import World, WorldConfig, register

class MyWorld(World):
    Config = WorldConfig

    def _regrow_rate(self): ...        # сколько еды за такт
    def _food_energy(self, body, ft): ...  # сколько даёт еда этого типа
    def _food_cap(self, ft): ...       # потолок на тип
    def _build_sensor(self): ...       # форма наблюдения
    def _on_birth(self, child, parent): ...   # пер-теловые признаки
    def _on_tick(self): ...            # динамика уровня мира
    def _perturb(self, body): ...      # изменения по ходу жизни

register("my_world", MyWorld)
```

Для пер-теловых поломок в `Body` есть `action_map` (перестановка действий) и
`sensor_mask` (маска наблюдения) — ядро применяет их само, см. `ShiftWorld`.
Произвольное состояние клади в `body.traits`.

Если добавляешь мир — добавь и проверку решаемости в тесты. Мир, который
убивает всех, снаружи неотличим от мира, который просто сложный, пока не
покажешь, что компетентное поведение в нём выживает.
